# Экономическая модель

Дополняет [product-proposal.md, Ограничения → Бюджет](product-proposal.md#операционные-ограничения) конкретными цифрами. Числа ниже либо измерены на реальных вызовах через настроенный LLM-эндпоинт, либо явно помечены как экстраполяция — методика указана, чтобы можно было проверить и пересчитать.

`LLMClient` считает реально потраченные токены на каждый вызов (`src/pr_review_agent/llm_client.py`, `_record_usage`) — но, в отличие от более ранней версии этого документа, стоимость больше не считается по статической таблице цен за токен. Провайдер по умолчанию — [Polza.ai](https://polza.ai/docs), унифицированный прокси перед ~400 моделями с собственным (и меняющимся) прайсингом на каждую; поддерживать для них статическую таблицу цен нереально, а устаревшая цена в отчёте хуже, чем её отсутствие. Вместо этого используется **реальная стоимость, которую провайдер сам возвращает в ответе** — `usage.cost_rub` (расширение поверх стандартной схемы OpenAI Chat Completions). `LLMClient` читает это поле напрямую и накапливает в `total_cost_rub`. Итог за run попадает в `Job.llm_input_tokens` / `llm_output_tokens` / `llm_cost_rub` и печатается CLI/отдаётся `/jobs/{id}` в gateway.

**Валюта — рубли**, а не доллары: Polza выставляет счёт в RUB (см. `polza.ai/docs`, «Оплата в рублях»), и `usage.cost_rub` — это и есть реальный биллинг, а не что-то, что нужно переводить по курсу.

## Измеренный прогон

Тот же встроенный demo-фикстур, что и раньше (`tests/fixtures/sample.diff`, 2 файла, 12 изменённых строк, репо `demo/`), прогнан через реальный эндпоинт (`LLM_BASE_URL=https://polza.ai/api/v1`, `LLM_MODEL=openai/gpt-4o`):

```bash
PYTHONPATH=src python -m pr_review_agent.cli analyze --diff-file tests/fixtures/sample.diff --repo-root demo
```

Результат (лог `llm_call_completed` за этот run):

| Агент | Input tokens | Output tokens | Итог |
| --- | --- | --- | --- |
| security_agent | 469 | 1 | завершился |
| test_coverage_agent | 467 | 59 | завершился |
| bug_agent | — | — | **timeout** (connection error, 30s + 1 retry) |
| quality_agent | — | — | **timeout** (connection error, 30s + 1 retry) |

**Итого за run: 936 input / 60 output токенов → 0.347679 ₽**, статус `completed_partial` (2 из 4 агентов).

### Операционная находка: таймауты на `openai/gpt-4o` через Polza

Как и находка про rate-limit на бесплатном тарифе Gemini в более ранней версии этого проекта, это не гипотетический риск — оба таймаута произошли в реальном измерительном прогоне выше. Дефолтный `request_timeout_seconds: 30` (`config.py`) оказался тесен для этой конкретной модели/провайдера при 4 параллельных вызовах. Оркестратор обработал это корректно — упавшие агенты помечены `agent_llm_unavailable`, run завершился как `completed_partial` с отчётом от оставшихся агентов и static-analysis (`docs/system-design.md` § 7), а не упал целиком. Практический вывод: при переходе на новую модель/провайдера стоит **сначала прогнать `eval/run_eval.py --llm real`** и посмотреть на `pipeline_stability`/таймауты, прежде чем полагаться на дефолтный `request_timeout_seconds` — возможно, его стоит увеличить в `config.yaml` для конкретно этой модели.

## Оценка стоимости за PR (экстраполяция, не таблица цен)

Из измерения выше: ~1000 токенов (input+output) на один успешный вызов агента ≈ **0.15–0.2 ₽**. Экстраполируя на полный PR (4 агента, без токенов на находки инструментов/retrieved context, которые в этом измерении были близки к нулю на игрушечном demo-репозитории):

| Сценарий | Строк diff | Оценка (4 агента, очень грубо) |
| --- | --- | --- |
| Измеренный (sample.diff, частично — 2/4 агента) | 12 | **0.35 ₽** (реально потрачено) |
| Малый PR (полные 4 агента) | 50 | **≈0.7–1 ₽** |
| Средний PR | 500 | **≈3–5 ₽** |

Это грубая экстраполяция от одного частичного измерения, **не эквивалент прежней формулы** (которая была откалибрована по полной таблице цен $/токен для конкретной модели Gemini) — модель, провайдер и валюта сменились, и полную формулу стоит пересчитать на реальном прогоне без таймаутов, когда будет собрано больше данных. Даже верхняя оценка для среднего PR — единицы рублей, что по-прежнему подтверждает предпосылку product-proposal.md «PoC должен быть реализован с минимальными затратами», просто без ложной точности старой таблицы.

## Сравнение моделей/провайдеров

Раньше здесь была таблица цен по конкретным моделям Gemini. Со сменой на Polza.ai (~400 моделей, у каждой своя и часто меняющаяся цена) поддерживать такую таблицу в документации означает гарантированно её рассинхронизировать с реальностью. Актуальные цены — **живой каталог `polza.ai/models`** (фильтр по провайдеру/модели), а не копия в этом файле.

Смена модели — один параметр в `.env` (`LLM_MODEL`) или `config/config.yaml` (`llm.model`), без изменений кода — см. [specs/serving-config.md](specs/serving-config.md). Имя модели включает провайдера (`openai/gpt-4o`, `anthropic/claude-sonnet-5`, ...).

## Что не включено (осознанно, PoC-scope)

- Стоимость самого GitHub API — $0 (публичные репозитории, анонимный или PAT-доступ в пределах free rate limit).
- Стоимость static-analysis инструментов — $0 (open-source, локальный CPU, миллисекунды на файл).
- Человеческий труд на разметку eval-датасета / ревью отчётов — не оценивается (вне экономической модели уровня API).
- Полная стоимость инфраструктуры под нагрузкой (масштабирование Job Store, мониторинг) — не оценивается, вне scope PoC.
