# Экономическая модель

Дополняет [product-proposal.md, Ограничения → Бюджет](product-proposal.md#операционные-ограничения) конкретными цифрами. В отличие от таблицы «на бумаге», числа ниже либо измерены на реальных вызовах Gemini API в этом проекте, либо посчитаны по формуле на основе этих измерений — методика и источники указаны явно, чтобы можно было проверить и пересчитать.

Начиная с этой версии PoC, `LLMClient` сам считает реально потраченные токены на каждый вызов (`src/pr_review_agent/llm_client.py`, `_record_usage`) и переводит их в доллары через `src/pr_review_agent/pricing.py`. Итог за run попадает в `Job.llm_input_tokens` / `llm_output_tokens` / `llm_cost_usd` и печатается CLI/отдаётся `/jobs/{id}` в gateway — это не отдельная «модель стоимости» сбоку, а часть системы.

## Источники данных

- **Цены** — [ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing), снято 2026-09-21, standard tier:

  | Модель | Input, $/1M токенов | Output, $/1M токенов |
  | --- | --- | --- |
  | `gemini-3.6-flash` (по умолчанию в проекте) | 0.75 | 3.75 |
  | `gemini-2.5-flash` | 0.30 | 2.50 |
  | `gemini-2.5-pro` (≤200k токенов) | 1.25 | 10.00 |
  | `gemini-3.1-pro-preview` (≤200k токенов) | 2.00 | 12.00 |

  Таблица зашита в `pricing.MODEL_PRICING_PER_1M_USD` — при смене `llm.model` в конфиге на модель не из списка `estimate_cost_usd()` кидает исключение, а не молча считает $0, так что устаревшая цена не может незаметно попасть в отчёт.

- **Расход токенов на реальный запрос** — измерен на этом же PoC, на `tests/fixtures/sample.diff` (2 файла, 12 изменённых строк) через `google.genai`'s `count_tokens` (не расходует квоту `generate_content`) и через реальные завершённые вызовы `generate_content` в этой сессии:

  | Агент | System prompt (fixed) | User content (diff+context) | Output (реальный пример) |
  | --- | --- | --- | --- |
  | bug_agent | 228 | 296 | 180 |
  | security_agent | 227 | 296 | 122 |
  | quality_agent | 235 | 296 | 237 |
  | test_coverage_agent | 232 | 296 | 79 |
  | **Итого (4 агента)** | **~920** | **~1184** | **618** |

  Итого на этот прогон: **2106 input / 618 output токенов** → **$0.0039** по цене `gemini-3.6-flash`.

## Формула

На один чанк diff (см. [system-design.md § 4](system-design.md#4-state--memory--context-handling) — чанк ≤ `chunk_size_lines`, по умолчанию 500 строк) четыре агента запускаются параллельно:

```
input_tokens_per_agent  ≈ 230 (fixed: isolation preamble + role prompt)
                         + ~25 × changed_lines_in_chunk   (diff text + section headers)
                         + tool_findings_tokens            (растёт с числом находок инструментов)
                         + retrieved_context_tokens        (символы/тесты/конвенции, см. specs/retriever.md)

output_tokens_per_agent ≈ 80–240  (наблюдаемый разброс; зависит от количества и «многословности» находок)

cost_per_chunk = 4 × (input_tokens_per_agent × $0.75 + output_tokens_per_agent × $3.75) / 1 000 000
cost_per_pr    = cost_per_chunk × число_чанков   (1 чанк, если diff ≤ max_diff_lines=2000; иначе PR режется на chunk_size_lines-кусочки)
```

`~25 токенов/строку` и коэффициент 230 для fixed-части — измеренные константы (таблица выше), не догадка. `tool_findings_tokens` и `retrieved_context_tokens` в этом измерении были близки к нулю (пустой `tool_findings`, минимальный `retrieved_context` на игрушечном demo-репозитории) — на реальном PR они добавляют токены пропорционально числу находок static-analysis инструментов; формула ниже даёт нижнюю границу, не точный прогноз.

Даже верхняя граница (PR на пределе лимита в 2000 строк) — **меньше $0.20**. Это подтверждает предпосылку product-proposal.md «PoC должен быть реализован с минимальными затратами» количественно, а не декларативно.

## Масштаб (при переходе на платный тариф)

Бесплатный тариф Gemini жёстко ограничен по throughput (см. ниже) и не подходит для продакшена — но даёт ориентир на масштаб при переходе на платный:

| Объём | Средний PR (~$0.01–0.04) | Оценка/месяц |
| --- | --- | --- |
| 10 PR/день (маленькая команда) | $0.1–0.4/день | **$3–12/мес** |
| 100 PR/день (средняя организация) | $1–4/день | **$30–120/мес** |
| 1 000 PR/день (крупная организация) | $10–40/день | **$300–1 200/мес** |

Плюс инфраструктура (Job Store, API Gateway) — вне LLM-стоимости. Для PoC-масштаба это локальный процесс, $0. Для продакшен-уровня — минимальная облачная инстанция (SQLite/Redis + FastAPI) оценочно **$5–20/мес** при указанных объёмах; детальный расчёт инфраструктуры — вне scope PoC (см. README.md, Out-of-Scope), приведён здесь только для порядка величины.

## Бесплатный тариф: не про деньги, а про throughput

На бесплатном тарифе `gemini-3.6-flash` стоимость запроса — $0, но throughput жёстко ограничен: в этой сессии эмпирически наблюдались `429 RESOURCE_EXHAUSTED` с лимитами **5 запросов/мин** и (отдельная квота) **~20 запросов/день** для одного проекта (см. `eval/README.md`, «Operational finding», и `src/pr_review_agent/rate_limiter.py`, добавленный именно по итогам этого наблюдения). Экономически это означает:

- Бесплатный тариф пригоден для **демонстрации и разработки** (единицы PR в день), но не для даже небольшой продакшен-нагрузки — 10 PR/день с 4 параллельными агентами каждый уже упираются в дневную квоту.
- Client-side `RateLimiter` (5 req/min по умолчанию) предотвращает *минутный* всплеск 429, но не может обойти *дневной* лимit — единственное решение для реальной нагрузки — платный тариф, на котором ограничение становится только $/токен (таблица цен выше), без искусственного потолка запросов.
- Разница между тарифами — не техническая, а сугубо про бюджет: тот же код, тот же `LLMClient`, только `GOOGLE_API_KEY` от платного проекта.

## Сравнение моделей (та же задача, разная цена/качество)

| Модель | Input $/1M | Output $/1M | Оценка стоимости среднего PR (500 строк) | Комментарий |
| --- | --- | --- | --- | --- |
| `gemini-2.5-flash` | 0.30 | 2.50 | **≈$0.017** | Дешевле, но старее поколение — не проверялось на этом наборе агентов |
| `gemini-3.6-flash` (default) | 0.75 | 3.75 | **≈$0.041** | Используется в этом PoC; лучший баланс цена/актуальность на момент написания |
| `gemini-2.5-pro` | 1.25 | 10.00 | **≈$0.071** | Для более сложных находок/рассуждений, если flash даёт много ложных срабатываний |
| `gemini-3.1-pro-preview` | 2.00 | 12.00 | **≈$0.111** | Самый дорогой вариант; в этой сессии дополнительно упирался в отдельную (более жёсткую) квоту биллинга |

Смена модели — один параметр в `config/config.yaml` (`llm.model`), без изменений кода — см. [specs/serving-config.md](specs/serving-config.md).

## Что не включено (осознанно, PoC-scope)

- Стоимость самого GitHub API — $0 (публичные репозитории, анонимный или PAT-доступ в пределах free rate limit).
- Стоимость static-analysis инструментов — $0 (open-source, локальный CPU, миллисекунды на файл).
- Человеческий труд на разметку eval-датасета / ревью отчётов — не оценивается (вне экономической модели уровня API).
- Полная стоимость инфраструктуры под нагрузкой (масштабирование Job Store, мониторинг) — приведена только порядком величины, детальный расчёт — вне scope PoC.
