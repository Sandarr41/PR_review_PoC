# Спецификация: Context Retriever

Роль в архитектуре — [system-design.md, раздел 5](../system-design.md#5-retrieval-контур).

## Назначение

Дополняет diff релевантным контекстом кода, который LLM не видит напрямую в diff (определения вызываемых функций/классов, связанные тестовые файлы, конвенции проекта), чтобы снизить количество ошибок reasoning из-за нехватки контекста — без индексации всего репозитория.

## Источники (sources)

- Локальный checkout репозитория на ревизии PR (та же версия, что и diff).
- Файлы конвенций проекта (README.md, CONTRIBUTING.md, .editorconfig — если присутствуют).
- Существующие тестовые файлы, относящиеся к изменённым модулям (по naming convention: `test_*.py`, `*_test.py` и т.п.).

## Индекс

PoC не использует персистентную vector DB. Индекс строится «на лету» для каждого run:

1. **Symbol index** — AST-based парсинг изменённых файлов и их прямых импортов (dependency в один «прыжок»).
2. **(Опционально) In-memory embedding index** — лёгкий эмбеддинг-индекс по изменённым и напрямую импортируемым файлам; включается только если позволяет context/latency budget. По умолчанию выключен в PoC (см. product-proposal.md, Технические ограничения).

## Поиск и reranking

- **Symbol resolution** — точный lookup по имени функции/класса, встречающемуся в diff, в пределах репозитория.
- **Similarity search (опционально)** — top-k (k=5) по cosine similarity эмбеддингов, ограничен файлами не дальше одного «прыжка» импорта от изменённого файла.
- **Reranking** — приоритет: (1) прямые зависимости изменённого кода, (2) относящиеся тестовые файлы, (3) файлы конвенций. Суммарный объём ограничен частью context budget (см. [specs/memory-context.md](memory-context.md)).

## Ограничения

- Работает только в пределах одного репозитория и одного PR — нет кросс-репозиторного знания.
- Не строит долгосрочный индекс — каждый run пересчитывает контекст заново (cost/latency trade-off, приемлемо для PoC-объёма PR).
- Точность symbol resolution зависит от статического анализа; сильно динамический код (`getattr`, `eval` и т.п.) может быть не резолвлен — retriever в этом случае возвращает пустой доп.контекст, а не ошибку (graceful degradation).
- Embedding-поиск не включён по умолчанию в PoC.
